# Private sync frontend — disabled draft

This branch implements the frontend; **it does not enable cloud sync**. `cloud-config.js` contains `enabled: false`, `policiesVerified: false`, an empty project URL and an empty publishable key. Default CSP is `connect-src 'none'`. Opening the private-sync dialog shows a setup state; there is no Auth client, account creation, telemetry or transmission of trips/files. The local planner remains usable.

The backend proposal is a separate, unmerged [review-only PR #3](https://github.com/sfox2006/Trip-Planner-/pull/3), reviewed at `fb0e2a534b23df5c873caed9887c7984046a0456`. This frontend implements its five `planner_api` RPCs and private `planner-attachments` bucket contract. No SQL, bucket/policy changes, dashboard changes or credentials are included here.

## Behavior after separately approved, verified configuration

- Confirmed individual email/password accounts; no anonymous login or shared password. Users enter their own passwords. Confirmation/resend/password recovery use PKCE and the exact root-page redirect. Root and `index.html` share the same Auth storage/Web Lock scope. URL codes/errors/implicit-token fragments are removed before processing; implicit sessions are never accepted.
- Tokens use sessionStorage by default. Explicit **Remember login** uses localStorage. Same-origin scripts can read either. PKCE verifier slots alone use localStorage for confirmation in a new tab, with a one-hour TTL. Signing out removes local Auth material and stops token refresh even if the logout request fails. It preserves trip/files and the owner-bound journal; account erasure is separate.
- Each data request snapshots a token, verifies that exact token with Auth `getUser`, checks confirmed expected identity and uses immutable authorization for RPC/Storage. Account transitions/signout invalidate pending verification and request authorization. Tokens/passwords never enter planner JSON, file records, sync journal or backup exports.
- Initial **Connect and merge** is explicit. It shows device/account counts first. Exact imported trip copies (including file byte hashes, ignoring fresh IDs) deduplicate; edited near matches remain separate. This browser copy is bound to one owner; another account cannot receive it. Back up and deliberately clear the origin's planner/file/sync storage before binding a different account. There is no automatic account migration.
- Online sync runs on an explicit button, reconnection/visibility, or a 60-second poll while open. No Realtime subscription or background synchronization when closed. Device online status alone does not prove a save. Synced confirms the current document revision and new uploads checked in that operation; **Check cloud files** separately verifies previously saved bytes. It is not continuous monitoring of cloud file availability. Offline changes remain local and are journaled before sending. Durable storage/quota failures block transmission and preserve local data.
- Documents use decimal-string revisions and compare-and-swap. Independent IDs/fields merge from a saved base. Competing edits, deletion versus edit and invalid combined references require explicit per-trip choices: keep cloud, or keep cloud plus a new device copy. Tombstoned IDs are never silently resurrected. Changes made during requests are rebased and kept; no timestamp-based overwrite. A stale save retries only by reading/merging the next revision.
- PDF/photo originals are reserved under an owner/object UUID path, uploaded immutably, then downloaded/hash-checked before their manifest is committed. Files/metadata survive interrupted acknowledgements. Missing acknowledged pending uploads can be recreated from durable originals; missing/corrupt referenced cloud files can be repaired from healthy local originals under new object IDs. Repair preserves pending edits and competing versions. Existing 5 MiB/file, 20 MiB/100-file limits apply; reservations and orphan bytes count against backend quota.
- Unfinished uploads are reviewed and explicitly selected for cleanup. Current cloud, queued, candidate and recovery references are protected. Cleanup reloads the owner journal, checks its generation, and uses the app's Web Lock. Destructive cleanup is unavailable in browsers without Web Locks. No automatic orphan expiry/deletion.
- A durable journal retains original/merged/candidate byte copies before local projection. The normal planner remains in localStorage and files in IndexedDB; those cannot be atomically committed together. Projection guards, rollback and a complete local recovery backup handle partial failures. Missing/reset text, missing file-store markers, or unexplained attachment loss pause sync rather than delete cloud data. Intentional in-app deletion still syncs. Restoring recovery requires an explicit reconnect.

## Privacy and local persistence

Cloud records/files would be plaintext protected by verified Auth/RLS and private Storage policies. This is **not end-to-end encryption**: Supabase/project administrators with privileged access can read them. Provider-managed infrastructure may keep operational logs. No analytics, map/embed integrations or third-party data transmission are implemented. The configured app sends data only to `https://psdfjframcinoryyklxf.supabase.co` over guarded Auth, REST and Storage endpoints. The service worker only caches public allowlisted app files; it never caches APIs, tokens, uploaded bytes or exports.

`personal-trip-planner.v1` remains the ordinary text key. `personal-trip-planner-files` is upgraded from IndexedDB v1 to v2 by adding a control store; existing attachments are retained. `personal-trip-planner-sync` stores one owner binding and an offline journal containing private planner text, file manifests and original Blobs, **without Auth tokens/passwords**. Projection/reset/revision markers are local metadata. Recovery/original/candidate copies use additional browser quota; clearing website data can destroy them. No browser storage is encrypted by this app. All sites on `sfox2006.github.io` share origin storage. Backups stay local and should be kept privately, outside this public repository.
